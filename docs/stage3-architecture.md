# Этап 3: архитектура Apexi 0.1

Дата: 2026-10-30. Основание: решения №10, №11 (Android, без сервера), №29 (Kotlin + Compose), №30 (Android 8–16), №31 (GitHub).

## 1. Слои и модули

```
:app      (Android-приложение)
  Экраны на Jetpack Compose, ViewModel, навигация
      │
      ▼
:data     (Android-библиотека)
  Room (SQLite): тренировки, подходы, самочувствие, настройки
  Загрузка контента из JSON (упражнения, шаблоны, тексты «почему?»)
  Экспорт и импорт резервной копии в файл
      │
      ▼
:domain   (чистый Kotlin, без Android)
  Модели: упражнение, шаблон, подход, тренировка, цвет дня...
  Правила: прогрессия, самочувствие, скрининг, разминка, оценка 1ПМ
  Автотесты на каждое правило
```

**Главное правило зависимостей:** `:domain` ничего не знает об Android, базе данных и экранах. Поэтому:

- правила можно проверить быстрыми автотестами без телефона;
- модуль можно перенести в Kotlin Multiplatform для iOS почти без изменений;
- замена базы данных или интерфейса не затрагивает правила.

## 2. Технологии

| Задача | Выбор | Почему |
|---|---|---|
| Язык | Kotlin | Решение №29 |
| Интерфейс | Jetpack Compose + Material 3 | Современный стандарт Android; путь к Compose Multiplatform |
| Навигация | Navigation Compose | Стандарт Google |
| База данных | Room (SQLite) | Стандарт индустрии; поддерживает Kotlin Multiplatform |
| Контент (JSON) | kotlinx.serialization | Работает в чистом Kotlin и в Multiplatform |
| Даты | java.time (Android 8+) | Встроено, решение №30 |
| Внедрение зависимостей | Вручную (простой контейнер), без фреймворка | Для MVP фреймворк (Hilt, Koin) — лишняя сложность |
| Тесты | JUnit + kotlin.test для `:domain`; тесты Room на временной базе | Критерий готовности MVP №3 |
| Сборка | Gradle (Kotlin DSL) с каталогом версий | Стандарт |
| CI | GitHub Actions | Бесплатно для публичных репозиториев |

Точные версии библиотек фиксируются на шаге M0 по актуальным официальным страницам и записываются в каталог версий (`gradle/libs.versions.toml`).

## 3. Данные

### Встроенный контент (только чтение, в `:data/assets`)

- `exercises.json` — упражнения: id, название, мышцы, оборудование, нагружаемые суставы, замены, описание техники, ошибки, источники, уровень уверенности.
- `templates.json` — 4 шаблона программ (решение №16).
- `texts.json` — тексты «почему?», предупреждения, тексты анкеты.

Контент версионируется вместе с кодом. Карточки упражнений пишутся на шаге M1 и утверждаются основателем группами.

### Данные пользователя (Room)

| Таблица | Что хранит |
|---|---|
| `user_profile` | Цель, опыт, выбранный шаблон, акцент на ягодицы, дата начала калибровки |
| `screening_result` | Только результат анкеты, отмеченные суставы, дата (решение №27) |
| `equipment_steps` | Шаги веса: штанга, ряд гантелей, стеки (решение №23) |
| `workout` | Тренировка: дата, день шаблона, цвет дня, заметка |
| `readiness_check` | Ответы на 4 вопроса самочувствия |
| `set_entry` | Подход: упражнение, вес, повторы, RIR (только последний подход, решение №24), разминочный или рабочий |
| `exercise_state` | Для правил прогрессии: текущий вес, диапазон, счётчик застоя, дата последнего выполнения |
| `cardio_entry` | Вид, минуты, скорость и наклон по желанию (решение №19) |

### Резервная копия

Экспорт всех данных пользователя в один JSON-файл и импорт из него (критерий готовности MVP №6).

## 4. Качество

- **Автотесты** на все правила `:domain`: каждый случай из документов Этапа 2 становится тестом.
- **CI:** при каждом изменении в GitHub запускаются тесты и собирается APK.
- **Никаких секретов в репозитории:** ключи подписи и пароли хранятся только локально и в секретах GitHub, которые основатель добавляет сам.
- **README** с описанием проекта, скриншотами и инструкцией по сборке.

## 5. Работа с репозиторием

- Ветка `main` всегда собирается и проходит тесты.
- Каждый шаг (M0–M6) делается в отдельной ветке и попадает в `main` через pull request. В истории GitHub видно, что и зачем менялось, это работает на портфолио.
- Сообщения коммитов на русском или английском (см. вопрос основателю в плане M0).
- Версии: 0.0.x на шагах разработки, 0.1.0 — готовый MVP.

## 6. Распространение версии 0.1

- APK публикуется в разделе Releases на GitHub; друзья скачивают и устанавливают его вручную.
- Для этого нужен ключ подписи релизной версии. Основатель создаёт его сам в Android Studio на шаге M6; пароли не передаются в чат и не попадают в репозиторий.
- RuStore и Google Play — Этап 6.

## 7. Что сознательно не делаем в 0.1

- Сервер, аккаунты, синхронизация (решение №11).
- iOS (решение №10); но `:domain` готов к Kotlin Multiplatform.
- Аналитика использования и сбор отчётов о сбоях с отправкой в интернет: данные не покидают телефон.
